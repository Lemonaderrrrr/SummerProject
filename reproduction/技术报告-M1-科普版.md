## 0. 一句话总览

我们在**电脑仿真里**,让一个开源的"AI 机器人大脑"(叫 **OpenVLA**)去完成"把碗放到盘子上"这类任务,**实测它要花多少算力/显存/钱**,好让做金融的队友(Nicky)拿这些成本数据写一份**具身智能的投资分析报告**。

## 1. 背景:几个概念先补上(小白必读)

### 1.1 具身智能 / VLA 是什么
**具身智能** = 有身体(机器人)的 AI:它要**看**、要**听懂指令**、还要**动**。
**VLA = Vision-Language-Action(视觉-语言-动作)模型**:一个能把
> **摄像头画面 + 一句人话指令 → 机械臂该怎么动**

一步到位算出来的 AI。比如你说"把黑碗放到盘子上",它看着画面,一步步输出机械臂的移动。

### 1.2 它凭什么会动?——神经网络
VLA 本质是一个**超大神经网络**。你可以理解成一个**带了 70 亿个可调旋钮的函数**:没人手写"看到碗该怎么动"的规则,而是用海量人类示范数据,自动把这些旋钮拧到"输入画面+指令、输出正确动作"。这个"7 亿/70 亿"的数量级叫**参数量**,是衡量模型大小的核心指标(我们用的 OpenVLA 是 **70 亿参数**,记作 7B)。

### 1.3 两条技术路线(项目要对比的)
| 模型 | 出品方 | 怎么"想出"动作 |
|---|---|---|
| **OpenVLA** | 开源社区 | **token 预测**:把动作切成一个个"词",像语言模型逐个"说"出来 |
| **π0 (pi-zero)** | Physical Intelligence | **flow matching**:把动作当连续信号,用另一种数学一次性"生成" |

这次报告只做完 **OpenVLA**;π0 是后续。

### 1.4 在哪里测?——LIBERO 仿真
真机器人又贵又慢,所以我们在**仿真**里测。**LIBERO** 是一套标准"考卷":一台仿真的 Franka 机械臂,桌上有碗、盘子、柜子,任务都是"把某个碗放到盘子上"的变体。仿真背后用 **MuJoCo 物理引擎**算物理、渲染画面。

### 1.5 "推理""评测""成功率"
- **推理(inference)**:拿训练好的模型直接用(输入→输出),不再改它。
- **评测(evaluation)**:让模型在考卷上做很多道题,统计它做对多少。
- **成功率**:做对的比例。比如 30 道题对 22 道 = 73.3%。

### 1.6 算力名词:HPC / Slurm / GPU / 显存 / 量化
- **GPU**:跑 AI 的显卡。我们用学校的 **A30**(24GB 显存)。
- **显存(VRAM)**:显卡的内存。模型必须先装进显存才能跑。**装不下就跑不了**。
- **HPC(高性能计算集群)**:一大堆服务器组成的"公共机房",这里指 UCI 的 **HPC3**。
- **登录节点 vs 计算节点**:你 SSH 进去落在**登录节点**(只能编辑文件、提交任务,✋不能跑重活);真正算力在**计算节点**,通过调度器 **Slurm** 排队申请。
- **量化(quantization)**:把模型权重从 16 位压成 **4 位**,体积缩到约 1/4(7B 模型从 ~16.8GB → ~6GB),这样便宜的小显卡也跑得动,精度几乎不掉。这是"降成本"的关键杠杆,也是我们项目的核心卖点之一。

## 2. 我们做了什么(里程碑 M1)

**一句话**:在 HPC3 上把 OpenVLA 的环境从零搭好,让它以 **4-bit 量化**在 LIBERO 上跑通一次完整推理评测,拿到第一组真实成本数据。

### 2.1 核心机制:闭环控制
评测时,模型在仿真里反复做这个循环(**记住它,所有机器人 AI 都是这个圈**):

```
仿真渲染当前摄像头画面
      ↓
画面 + 指令("pick up the black bowl…") 喂给 OpenVLA
      ↓
模型输出一个 7 维动作(机械臂 xyz 移动 + 3 个旋转 + 夹爪开合)
      ↓
仿真执行动作,进入下一帧
      ↓
回到第一步,直到任务成功 or 超时
```

一个任务从头做到尾叫一个 **episode**。我们跑了 10 个任务 × 3 次 = 30 个 episode。

### 2.2 结果(第一组成本数据)
| 指标 | 实测值 |
|---|---|
| 成功率 | **73.3%**(22/30) |
| 显存峰值 | **6.2GB**(4-bit) |
| 模型大小 | 14GB(磁盘) / 70 亿参数 |
| GPU | A30(学校免费队列,**不烧付费额度**) |
| 单次评测耗时 | 46 分钟 |

> 直觉验证:我们抽了一个成功 episode 的画面,机械臂确实**有目的地**探向柜子、抓起碗、移到盘子——不是乱动。这就是"模型真的在工作"的肉眼证据。

## 3. 手把手复现(照我们的 HPC3 路径)

> ⚠️ 这一节是我们**实际跑通**的完整流程。你若有 UCI HPC3 账号可以照做;没有账号也能读懂每一步在干嘛。所有脚本都在本仓库 `reproduction/scripts/`。

### 3.1 前置准备
1. **申请 HPC3 账号**:用 UCInetID 邮箱发信给 `hpc-support@uci.edu`(模板见 `reproduction/环境搭建.md`)。会拿到免费的 `free-gpu` 队列使用权。
2. **连 UCI VPN**(校外必须):Cisco Secure Client → `vpn.uci.edu` → 第二个密码框输 `push` 触发手机 DUO。
3.(可选但强烈推荐)**配 SSH key 免密**:生成带口令的密钥、存进电脑钥匙串、公钥装到 HPC3,之后登录免密码免 DUO(细节见 `reproduction/笔记.md`)。

### 3.2 登录 + 诊断(先看清楚机房有什么)
```bash
ssh <UCInetID>@hpc3.rcic.uci.edu          # 输密码 + DUO
sinfo -p free-gpu -o "%P %G %D %t"        # 看免费队列有哪些 GPU
module avail 2>&1 | grep -iE "conda|cuda" # 看可用的软件模块
ls -ld /pub/$USER                          # 确认大文件存储可用
```
> **关键发现**:免费 `free-gpu` 队列里有 **V100(16GB)、A30(24GB)、A100(80GB)**。这一步决定了后面用哪张卡(见 3.4 的坑 #9)。

### 3.3 建环境(一条命令搞定)
把 `reproduction/scripts/build_openvla.slurm` 传上去、提交作业:
```bash
sbatch build_openvla.slurm     # 它会自动建 conda 环境、装 OpenVLA + LIBERO + 修好所有依赖
squeue -u $USER                # 看作业状态:PD=排队, R=运行中
```
> 大文件(模型、环境)全放 `/pub/$USER`,别塞 `$HOME`(有配额)。

### 3.4 我们踩过的 9 个坑(这才是复现最费时的部分)
搭 AI 环境,一半时间在跟**依赖版本冲突**打架。以下每个坑 `build_openvla.slurm` 里都已修好,列出来让你明白为什么:

1. **flash-attn 跨盘报错**:装它时文件要跨不同硬盘搬运,报 `Invalid cross-device link` → 改用官方预编译包 + 把临时目录指到同一块盘。
2. **protobuf 冲突**:一个子依赖偷偷升级、要新版 protobuf,和 TensorFlow 打架 → 钉死 `protobuf==4.25.3`。
3. **numpy / opencv 冲突**:被顶到 2.x,和老组件不兼容 → 钉死 `numpy==1.26.4`、`opencv-python==4.9.0.80`。
4. **LIBERO 装了却 import 不到**:它的包结构特殊 → 用 `pip install -e . --config-settings editable_mode=compat`。
5. **LIBERO 首次运行卡住**:它会交互式提问,批处理里没法回答 → 预先喂一个默认答案生成配置。
6. **缺 bitsandbytes**:4-bit 量化必需,默认没装 → `pip install bitsandbytes==0.43.1`。
7. **accelerate 太新**:比模型预期的版本新,加载 4-bit 时报错 → 降回 `accelerate==0.30.1`。
8. **mujoco 太新**:物理接口函数签名变了,机械臂控制器崩溃 → 降回 `mujoco==2.3.2`。
9. **🔑 V100 跑不了 flash-attn(最坑)**:OpenVLA 用的加速算子只支持 **Ampere 架构及更新**的卡,而 **V100 是更老的 Volta 架构** → 在 V100 上每一步推理都静默报错、成功率变成 **0%**。**解决:改用 `free-gpu` 里的 A30(Ampere 架构,同样免费)。**

> 通用教训:**旧项目的依赖常只写"≥某版本"却不封顶,几年后新版本发布、行为一变就崩。** 复现别人的工作,"把环境跑起来"本身就是一道大坎。

### 3.5 跑评测(= M1)
提交 `reproduction/scripts/run_m1.slurm`:
```bash
sbatch run_m1.slurm
# 它做的事:激活环境 → 用 A30 → 4-bit 加载 OpenVLA → 在 LIBERO-Spatial 上跑 30 个 episode
```
核心命令(脚本里已写好):
```bash
python experiments/robot/libero/run_libero_eval.py \
  --model_family openvla \
  --pretrained_checkpoint openvla/openvla-7b-finetuned-libero-spatial \
  --task_suite_name libero_spatial \
  --load_in_4bit True \
  --center_crop True \
  --num_trials_per_task 3      # M1 用 3 快速跑通;严格复现要 50
```

### 3.6 看结果

- **成功率 73.3%** → 模型确实能完成任务(远高于瞎动的 0%)。

## 5. 诚实的局限(很重要,别跳过)

做研究,数据**怎么报**和数据本身一样重要。这一节讲清我们数据的边界。

### 5.1 成功率的误差棒很大
成功率是个**比例估计**,样本越少越飘。我们只跑了 **30 个 episode**:
- 用统计公式算,73.3% 的 **95% 置信区间约为 [57%, 89%]**(即真实值可能在这么宽的范围里)。
- 官方公布的 OpenVLA 在这项任务上是 **84.7%**(来源见参考),而 84.7% **正好落在我们的误差区间内**。

**结论:用 30 个样本,我们其实无法判断自己是"低于"还是"等于"官方——统计上区分不开。** 说"我们复现出了 84.7%"或"我们比官方差"都不严谨。

样本量对误差的影响:
| 样本量 | 成功率误差(约) |
|---|---|
| 30(我们 M1) | ±16% |
| 200(下一步 bf16) | ±5.5% |
| 500(官方每种子) | ±3.5% |
| 1500(官方总) | ±0.9% |

### 5.2 我们和官方复现的差距在哪
| 维度 | 官方 | 我们 M1 |
|---|---|---|
| 样本量 | 1500(500×3 种子) | 30(1 种子) |
| 精度 | bf16(满血) | 4-bit(量化) |
| GPU | A100 | A30 |
| 模型/任务/协议/软件版本 | — | **完全一致** ✅ |

### 5.3 为什么受限:免费算力的天花板
官方那种 1500 次 × 多种子在 A100 上跑;我们在**免费、可被抢占**的队列上,单次 500 rollout 就要约 10 小时,中途被抢占还得从头再来。**这就是免费档的硬约束。**

### 5.4 但对本项目影响有限
要分清两类数:
- **成本数(显存、模型大小、延迟)= 确定性的,测一次就准** → 这是项目主料,**可靠**。
- **成功率 = 需要大样本才准的估计** → 只要**永远带样本量和误差棒报**、不硬下结论,就是诚实可用的数据。

> 换句话说:我们复现的**方法忠实**、**成本测量可靠**;唯独**成功率**因免费算力受限,只能给一个带误差棒的估计——如实标注即可。

## 6. 项目全景与后续计划

```
P0 学习+环境 ─▶ [M1 ✅ 你在这] OpenVLA 4-bit 跑通
P1 推理评测 ─▶ 加大样本 bf16 复现;装 π0 用同样条件对比 → 出成本对比表(交 Nicky)
P2 LoRA 微调 ─▶ OpenVLA 微调一个任务,实测训练 GPU 工时 → 折算训练成本
P3 成本建模 ─▶ 训练/推理/数据三块成本模型
```

**方法学铁律(贯穿全程)**:OpenVLA 与 π0 对比时,**同一张卡、同样样本量、同样评测协议**,只换模型,保证两边可比;成功率一律带误差棒报。

**给 Nicky 的交付**:一张结构化数据表 `reproduction/results/runs.csv`(原始实测)+ 派生的成本模型(带公式和假设,measured 与 estimated 分开标)。
