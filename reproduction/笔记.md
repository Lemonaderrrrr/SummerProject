### OpenVLA + LIBERO 环境构建(实战 · 一堆依赖坑)
环境装在 `/pub/lihonz3/envs/openvla`(conda,py3.10),代码 `/pub/lihonz3/{openvla,LIBERO}`。
可复现配方已固化进 `scripts/build_openvla.slurm`。踩的坑按顺序:

1. **flash-attn 跨盘 rename 失败** —— 源码编译时下预编译 wheel,要从本地盘 `os.rename` 到 beegfs 上的 pip 缓存,跨文件系统报 `Invalid cross-device link`。
   → **修**:直接 `pip install` 官方预编译 wheel(`flash_attn-2.5.5+cu122torch2.2cxx11abiFALSE-cp310`),cu122 兼容 torch 的 cu121 运行时。顺带把 `TMPDIR` 指到 /pub 同盘。
2. **protobuf 冲突** —— tf-datasets 把 `tensorflow-metadata` 拉到需 protobuf5 的新版,和 tensorflow 2.15(protobuf4)冲突,`import prismatic` 报 `cannot import name runtime_version`。
   → **修**:`tensorflow-metadata==1.14.0` + `protobuf==4.25.3`(4.25 同时喂饱 tf<5 和 wandb>4.21;protobuf 向后兼容,老 pb2 能跑)。
3. **numpy / opencv 冲突** —— `libero_requirements` 把 numpy 顶到 2.x、opencv 到 4.13(要 numpy2),和 tf2.15 / robosuite1.4.1(要 numpy<2)冲突。
   → **修**:`numpy==1.26.4` + `opencv-python==4.9.0.80`。
4. **LIBERO import 不到** —— 顶层 `libero/` 无 `__init__.py`(隐式命名空间包),新 setuptools 严格 finder 模式映射为空。
   → **修**:`pip install -e LIBERO --config-settings editable_mode=compat`。
5. **LIBERO 首次 import 交互提问** —— 问是否自定义数据集路径,batch 里 stdin 空 → `EOFError`。
   → **修**:`echo N | python -c "from libero.libero import benchmark"` 生成 `~/.libero/config.yaml`(默认路径)。
6. **bitsandbytes 缺失** —— 4-bit 量化必需,OpenVLA 默认没装 → `pip install bitsandbytes==0.43.1`。
7. **accelerate 太新** —— OpenVLA 只写 `accelerate>=0.25.0`(没封顶),pip 装了最新 1.14.0,和 transformers 4.40.1 内部行为对不上:加载 4-bit 时 `dispatch_model` 去 `.to()` 量化模型 → `ValueError: .to is not supported for 4-bit`。
   → **修**:降回同期版本 `accelerate==0.30.1`。**教训:依赖只写下限不封顶,是复现旧项目头号陷阱。**
8. **mujoco 太新** —— robosuite 1.4.1 只写 `mujoco>=2.3.0`(又没封顶),pip 装了 3.10.0,`mj_fullM` 函数签名变了 → robosuite 控制器 `TypeError: mj_fullM() incompatible arguments`。
   → **修**:降回同期 `mujoco==2.3.2`。冒烟测试 `robosuite reset` 通过、EGL 离屏渲染出图 (128,128,3) ✓。

**最终工作版本(pin)**:python 3.10 · torch 2.2.0+cu121 · flash-attn 2.5.5 · transformers 4.40.1 · **accelerate 0.30.1** · peft 0.11.1 · bitsandbytes 0.43.1 · tensorflow 2.15.0 · protobuf 4.25.3 · numpy 1.26.4 · opencv-python 4.9.0.80 · robosuite 1.4.1 · **mujoco 2.3.2** · libero 0.1.0。

### 🔑 关键坑 #9:V100 跑不了 flash-attn(0% 成功率的真凶)
- 首次 M1(53809480)端到端跑完但**成功率 0/30**。逐层排查:norm_stats 对、图像渲染正常(抽帧确认)、但每步 rollout 报 `Caught exception: FlashAttention only supports Ampere GPUs or newer` 被 try/except 静默吞掉 → episode 立刻夭折(1 帧视频、12s/ep)→ 模型一次都没真正推理。
- **根因**:V100 = **Volta**(compute 7.0),flash-attention-2 要求 **Ampere+(≥8.0)**。OpenVLA 写死 `attn_implementation="flash_attention_2"`。
- **修法**:换 free-gpu 上的 **A30(24GB,Ampere)**,`--gres=gpu:A30:1` —— 同样免费、节点更多(16 vs 12),flash-attn 原生可用。4-bit 仍测得 ~7GB 占用。
- **对成本故事的影响**:"OpenVLA 4-bit 只要 ~7GB" 依然成立(显存占用与卡型无关);但 **"能在 16GB V100 上跑" 需额外把 attn 改成 sdpa/eager**(留 P1 作为 16GB 方案补充)。
- 教训:装得上 ≠ 跑得动。flash-attn 能在 V100 上 pip 装成功,但运行时才因架构报错。**选卡要先看 compute capability。**

> **π0.5 vs OpenVLA(核心对比,同 A30 / libero_spatial / n=200)**:
> - 能力:**π0.5 98.5% vs OpenVLA 83.5%,高 15 分**(远超误差棒 → 统计显著,flow matching 这代明显更强)。
